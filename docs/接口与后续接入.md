# 接口边界与后续接入

当前前端直接调用 `src/data/store.js` 的演示数据与本机浏览器存储。并未签发或验证 JWT，没有真实文档识别服务，也没有向外部上传企业资料。`backend/app/main.py` 仅提供 FastAPI 健康检查和能力说明，前端运行不依赖后端。

## 本次 OA 前端实现

`src/data/auditWorkflow.js` 管理本机流程，`src/views/OA.vue` 提供企业填报与政府办理界面。流程为：待填报 → 已提交 → 资料审核 → 现场考察 → 退回修订 → 企业修订 → 再次提交 → 复核办结。

填报草稿与企业详情相互独立，仅在首次进入或手动同步时复制四部分数据。每次提交单独保存 snapshot、检查清单、接收单位、提交时间和版本号。审核意见、现场记录、修订回复与该版本关联；后续修改不覆盖旧提交快照。省、市账号查看辖区内已提交记录，县级接收账号执行办理操作。这里的权限和版本隔离属于前端交互，不提供服务端安全保证。

首次加载旧本地数据时只补齐缺失字段，不覆盖已有企业信息、资料文件和表格。关联报告或提交版本的原始文件保留，防止本地引用失效。

后续应将提交、受理、意见、考察、退回、修订提交、办结迁移为服务端事务，增加真实鉴权、版本号冲突检查、持久化日志和附件授权。现阶段没有新增后端业务接口。

## DeepSeek Harness 对接设计

参考桌面 deepseek-harness 的简洁会话区、资料引用、输入区与工具栏设计，当前用 Vue3 重写界面，不直接嵌入其 React/Cordis 运行时。对话使用明确标注的本地演示回复；“准备识别任务”只保存任务草稿与字段清单。

接入时由服务端代理 Harness。将企业范围、审核轮次、资料 ID、年度、适用标准版本和提示词一起传入。结果应至少包含：字段名、数值、单位、统计边界、文件 ID、页码、原文摘录、识别置信度、核实状态。返回的指标必须先进入确认队列，再由企业人员写入表格。缺失数值应保持为空，不自动补造。

## 标准与表格

`src/data/domain.js` 的 surveyTemplates 是用户提供正式标准前的结构样例。目前只计算产品合计、原辅材料合计、折标能源合计、新鲜水合计及两个单耗；不同污染物不跨类别求和。暂未配置权重、限定性指标或正式评级阈值。

用户给出的“东宇氮氧化物平衡图”并未随本次文件提供，因此当前提供可编辑的物料 / 污染物流向结构，未声称复刻该图。后续可导入其节点、数量、边界与单位，并配置守恒校验。

## 工艺编辑器

采用 [Vue Flow](https://vueflow.dev/guide/)（MIT）。支持拖动节点、从连接点拉线、双击编辑、选择后删除、视图缩放、物料流量标注和 JSON 导出。工艺分为生产、废水、废气；两个审核阶段共享同一轮的图数据。Vue Flow 负责图形交互，平衡核算需另外实现。

表格采用 [vxe-table](https://github.com/x-extends/vxe-table) v4，沿用原项目版本。业务表格通过 DataTable.vue 统一实现，保留列宽调整、双击编辑、固定计算行与来源依据。
